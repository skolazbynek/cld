Missing Tools · Problem

No Docker inside

Half of my work is containers. Claude has to run them to see whether its own change works.

The work needs it

Build an image, start it, call it, read the log.

The container has none

No docker socket, no daemon, no sibling containers.

A shared socket would let one container control every other one
Missing Tools · Problem

No secrets either

Tokens, passwords and .env files stay on the host. Testing and logging in both need them.

The work needs it

A token for the API, a password for the database, a real environment to run against.

The container has none

No .env, no keys, no host checkout.

A pasted token ends up in the transcript
A mounted .env reaches every agent
